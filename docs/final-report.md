# 本地演示交付报告

## 完成状态

已将现有功能收尾为可本地启动、复现和展示的学习项目。本轮不继续增加业务功能，也未推送仓库或公开部署。
实际入口为 **http://localhost:8000/**，当前运行模式保留为 **DeepSeek / deepseek-flash**，并保留原Key、数据库密码与JWT密钥。
模型配置就绪不等于本轮重新做过真实联网请求。

### 当前准确启动命令

```bash
cd /home/sun/projects/campus-assistant
docker compose up -d --build
docker compose ps --all
curl --fail http://127.0.0.1:8000/ready
```

无需激活`.venv`。浏览器登录/注册的是本项目账号；已有账号和历史继续使用。
首次在新目录复制项目时先运行 `python3 -m scripts.setup_env`，已有`.env`不会被覆盖。
停止使用 `docker compose stop`；重新启动使用 `docker compose up -d`；配置变化需重建app容器读取环境。

## 实际完成的功能与部署

- 复用JWT/Argon2认证、按用户隔离的会话和消息、指南查询、文档检索和鉴权原件入口。
- 新回答策略允许一般知识分析、普通交流、评价和学习规划；具体金额、资格、期限、审批要求须有依据。
  时效信息只限定未核实部分，不整段拒答。检索缺口交给模型，模型可解释已知条款并给建议。
- 本轮沿用策略版本 `2026-10-20.analysis-v2`；旧缓存按明确会话键重建，保留数据库历史，无全库Redis清理。
- 引用仅保留实际输出的合法编号；前端不把候选资料自动当作回答依据。奖助资料版本和对象/例外约束仍有效。
- Dockerfile固定Python 3.12官方slim基础镜像摘要，运行依赖固定版本，应用UID10001，stdout/stderr日志有轮转。
- `.dockerignore`采用白名单；镜像不包含`.env`、`.venv`、本地缓存、测试目录或验收记录。
- Compose增加app和单次migrate，容器内使用postgres/redis服务名；数据库、Redis和网页端口继续只绑定本机。
- 初始化服务以PostgreSQL会话锁串行迁移和幂等导入；app等待初始化成功，进程自身不迁移、不重置数据库。
  Redis为可降级缓存，不要求其健康后才能启动app；保留健康检查用于观察状态。
- `/health`保持原契约；新增`/ready`要求数据库可用，Redis故障时返回可降级状态。

## 部署验收与数据保留

先检查端口与进程，确认8000由本项目`.venv`中的uvicorn开发服务占用。
先在备用端口、随机隔离数据库验证同一个应用镜像；通过后只停止已核对归属/目录/命令的本项目开发父进程，未停止无关服务。

正式切换后实际检查：

- app healthy，migrate退出0；PostgreSQL/Redis健康，网页、配置、指南、受保护路由和原件读取正常。
- 开发数据库没有插入部署测试账号。真实注册/密码登录在同镜像隔离库中验收；正式服务的受保护只读检查使用本机签发的临时令牌，不索取用户密码，不保存令牌。
- 原数据库的指南、账号、会话、消息及资料记录保留（公开版省略个人库记录数）。
  对固定业务表逐行计算内存摘要比较，初始化前后及app重启后记录完全一致；不把行内容或摘要写入交付记录。
- `.env`前后字节一致，两个原命名卷 `campus-assistant_postgres_data` / `campus-assistant_redis_data` 保留。
- 正式app重启后记录及JWT签名仍有效；本轮部署和回归真实API调用0次。
