# 面试展示与技术取舍

## 30秒介绍

这是一个面向校园事务咨询的检索增强问答学习项目。我用FastAPI提供认证、会话和流式接口，PostgreSQL持久化记录，Redis缓存短期上下文；将三份学校资料按条款和表格分块，回答附带可展开的引用和鉴权原件入口。项目使用DeepSeek异步流式接口，保留mock演示模式，通过Docker Compose运行。

## 建议展示顺序

1. 说明业务目标、个人学习项目和资料版本边界。
2. 展示登录、会话历史、资料问题和来源卡片；明确演示模式。
3. 展示跨轮追问、停止生成、刷新后历史恢复。
4. 打开代码定位关键实现，再展示验收证据与尚未真实覆盖的部分。

## 关键代码与讲解

| 话题 | 代码入口 | 应讲清楚的内容 |
| --- | --- | --- |
| 流式请求生命周期 | app/chat.py、app/deepseek.py、app/web/sse.js | 事件与网络块的区别；预检、状态更新、断开与上游释放；JSON和SSE错误阶段 |
| 历史与缓存 | app/context_cache.py、app/conversations.py | 数据库为准；只保留已完成轮次；策略版本变化、Redis故障和过期回源 |
| 鉴权与越权 | app/security.py、app/conversations.py | 哈希与JWT；身份由后端确定；其他用户记录与不存在记录均返回404 |
| 资料检索 | app/reference_loader.py、app/reference_search.py | 条款和表格结构；双字词面评分和主题规则；没有向量检索或BM25 |
| 引用可信度 | app/reference_citations.py、app/references.py | 编号来自实际检索；版本、哈希和定位；编号合法不等于语义完全正确 |
| 部署一致性 | compose.yaml、scripts/initialize_database.py | 单次迁移、数据库锁、幂等导入；Redis可降级；非root镜像 |
| 测试隔离 | scripts/test_database.py、tests/conftest.py | 唯一临时库、随机测试密钥、明确的Redis键；不删除真实数据 |

## 可诚实说明的取舍

- 三份小文档先采用可解释的检索方式，简化成本与部署；同义表达召回能力和文档扩展性有限。
- 原生前端减少依赖，重点处理SSE分块、滚动与取消；不是大型前端工程体系。
- 当前Compose使用单应用worker，未做多节点部署与性能基准；不把功能测试写成高并发成果。
- 测试优先覆盖权限、状态与数据一致性；真实模型验收与固定响应测试分别记录。
- 校园具体政策基于提供的文件，一般分析允许模型发挥；资料不足只限制缺失事实，不整体拒答。
