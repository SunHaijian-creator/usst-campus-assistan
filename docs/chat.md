# 会话与流式接口

## 接口

`POST /conversations/{id}/chat` 使用Bearer令牌认证，接收消息内容并以SSE输出回复。访问前检查会话归属、参数和生成状态。

| HTTP状态 | 含义 |
| --- | --- |
| 401 | 本项目登录令牌无效或过期 |
| 404 | 会话不存在或不属于当前用户 |
| 409 | 同一会话正在生成，暂不可重复写入或删除 |
| 422 | 请求参数不符合要求 |
| 503 | 所需模型配置不可用 |

开始响应前的错误使用HTTP状态返回；开始流式响应后的错误使用SSE事件返回。

## SSE事件

| 事件 | 内容 |
| --- | --- |
| `meta` | 消息标识、运行模式及候选资料 |
| `delta` | 新增回复文本 |
| `done` | 完成信息及实际引用 |
| `error` | 生成错误及可读说明 |

候选资料不直接等于回答使用的来源。完成后的来源卡片与保存的消息引用对应。

浏览器使用带Authorization请求头的POST fetch读取流。网络数据块与SSE事件边界独立，解析器缓冲跨块事件，并处理同一数据块中的多个事件。

## 持久化与取消

消息状态包括 `generating`、`completed`、`failed` 和 `cancelled`。PostgreSQL保存消息文本、状态及引用。

同一会话只允许一个生成任务，使用会话行锁和唯一约束协调短事务。模型等待期间不持有长数据库事务。完成、失败、超时及断开均结束生成占用；过期生成记录可恢复。

点击停止生成或客户端断开后，后端关闭上游流并保存取消状态。部分文本可保留在历史中，失败或取消的回复不进入正常上下文。

## Redis上下文

默认缓存最近6轮已完成问答，总长度上限12000字符，TTL为600秒。缓存无效、过期或不可用时从数据库恢复。

数据库是历史记录的可靠来源。删除会话同步清理对应缓存，缓存操作失败不能代替数据库提交结果。

启动、模型配置和测试命令见[README](../README.md)与[模型接入](deepseek.md)。
