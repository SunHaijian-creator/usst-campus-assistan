`--stage-only` 仅校验并复制文件。暂存遇到已有不同内容文件会拒绝覆盖；导入遇到同一原件的
提取文本或既有片段内容变化会拒绝静默修改，需人工核对提取版本。文档以逻辑键+原件哈希去重，
片段以文档+稳定片段键去重，导入事务使用项目专用 advisory lock 防止并发重复。
不同原件版本可保留旧记录，检索只用本次导入的 active 版本；历史引用仍能定位旧记录。
本导入器针对这三份资料，不是任意 DOC/PDF 的通用抽取器，新版文件需复核解析规则与表格。

## 检索和模型输入

采用中文主题路由、双字词面匹配与章节规则，适合当前 29 个可检索片段。
覆盖奖学金/学业奖学金/国家助学金、中期考核、开题/审核后修改/置未审核等表达。
相关问题优先检索文档；文档域未导入或无依据时不拿虚构指南冒充依据。
校园卡补办、教室借用等原有示例仍走原指南检索。明确的短追问可沿用上一轮问题检索。
这不是通用语义检索，未覆盖的新说法可能需要补充规则，不承诺任意自然语言都能命中。

模型输入仍由固定 system 约束、独立 JSON `reference_data`、已完成历史和当前问题组成。
文档正文只放在参考数据中，不能成为 system 指令，也不执行其中的链接、脚本或操作要求。
当前问题只发送一次。未核验的流程图片段不会进入检索结果或模型输入。

对于奖助金额和比例，联检第一条适用对象及第八至十条管理例外；学业奖学金同时检索
阶段定义、评定条件和完整五行表格。提示词要求金额、比例连同适用对象及相关例外解释，
严格保留“奖学金”和“助学金”的措辞差异。服务端仅在实际引用奖助文件时补齐缺失的年度提示，
不再把整段适用对象及例外原文固定拼接到所有回答；来源卡片可查看实际引用的原文。

所有奖助回答明确说明：**依据所提供的2024年文件，当前适用性尚未核验**。
问今年/最新标准、其他适用对象或原文缺失的具体要求时，将具体资料缺口传入模型，
要求限定不确定的部分、解释已知内容并提供查询建议，不再替换为整段固定拒答。
一般学校评价、专业选择与学习规划允许模型分析，无检索结果也会调用配置的模型。
例如国家助学金原文记载年标准及按月划拨，但不能自行以 6000÷12 推算月实发金额。

## 引用、原件与鉴权

每次检索由服务端分配 `R1`、`R2` 等编号，并与实际片段 ID、文档、哈希、定位和摘录绑定。
SSE `meta.references` 是本轮检索候选快照（`references_status=retrieved`）。
`done.references` 与消息表 JSONB 仅保存回答实际引用的片段；前端完成后展示这些来源。
一般分析无需引用，不相关或未使用的检索结果不会变成来源卡片。刷新、多轮后仍使用原回答的编号快照。
模型只能使用这些编号。流式校验会缓存跨数据块的引用标记，对未检索编号、旧的数字/指南编号、
不完整或错误格式的编号发 `invalid_citation`，保存为 `failed`，不发 `done`，不进入正常上下文。
该校验确认引用定位合法性，不等于已经自动验证模型每句话的语义与原文完全一致。

前端来源卡片显示文档名称、版本、栏目/条款/物理页、警示和原文摘录；表格保留结构化列。
可以查看片段定位、打开 PDF 或下载 Word。PDF 浏览器不支持预览时提供原始文件下载后备页。

新增接口都需要原有 Bearer JWT：

| 接口 | 用途 |
| --- | --- |
| `GET /references/search?q=...` | 只检索原文与资料边界，不调用模型 |
| `GET /references/chunks/{id}` | 读取片段、定位、版本、原件哈希 |
| `GET /references/documents/{id}/original` | 读取登记的原件，重新核对文件哈希 |

这是项目共享参考库，已登录项目账号可读；自己的会话与消息仍执行原来的用户隔离。
原件放在静态目录外。请求只接受数据库 ID，不接受客户端服务器文件路径；拒绝路径越界、
符号链接、未知类型或哈希不一致的原件。前端用 Authorization 请求头获取原件，再创建本机 blob，
不把 JWT 放入下载 URL。响应使用 `private, no-store`，不清空任何业务缓存。

## 提取限制和已完成核对

- 奖助 PDF：已经本机渲染查看物理页 2～6；五组表格对应为第一阶段一等 20%/5000、二等 80%/3000，
  第二阶段一等 5%/12000、二等 35%/8000、三等 50%/4000，单位均为元/年/生。
  第二阶段比例相加为 90%，按原文保留，不改为 100%，也不解释原文未说明的其余比例。
- 第五条完整保存物理页 4、5 的学院/学校两级公示要求；第十一条完整保存物理页 5、6 的监督机制内容。
- 本机临时 PyMuPDF 进一步从原 PDF 表格提取列并核对五行关系，并将两个跨页条款与原 PDF 文本逐字去空白比较。
  均通过，记录在 `data/references/usst/pdf-verification.json`。PyMuPDF 只在 `/tmp` 用于本次检视，不是项目运行依赖。
- 中期考核 DOC 是空白模板。已修学分、开题时间和签字日期的空白栏不能当成最低学分或截止日期。
- 开题 DOC 只使用四条正文注释。文本框标签单独保存但 `usable=false`，不按排列生成完整办理顺序。
  原文“把改研究生”等文字保持原样，不擅自订正。
- DOC 没有可靠分页，因此引用栏目或注释编号，绝不填造 PDF 式页码；历史 HTTP 地址没有联网验证或自动打开。

### 仍需人工核对

1. 三份文件的官方来源、真实性、当前有效性及有无后续修订；尤其 2024 年奖助文件。
2. 中期考核的实际学分门槛、截止时间及学院完整管理要求，模板本身不足以确认。
3. 原 DOC 中开题流程图的箭头、分支及完整办理顺序；核对前继续禁用图中文字步骤。
4. Word 原件的真实分页/版式与原文可疑笔误；历史系统网址现在是否可用。
5. 模型真实回答效果需另外授权少量验证；本阶段没有追加付费请求。
