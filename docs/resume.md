# 简历与面试材料

## 技术栈

Python 3.12、FastAPI、Pydantic Settings、SQLAlchemy 2.x、Alembic、PostgreSQL 17、Redis 7、
JWT/PyJWT、Argon2/pwdlib、httpx、SSE、原生 HTML/CSS/JavaScript、Docker Compose、pytest、Playwright。

## 项目简介（可按版面缩写）

**上理办事助手｜校园资料检索与多轮问答学习项目**

面向校园事务咨询，搭建支持项目账号、个人会话历史、文档出处和流式回复的本地Web应用。
接入DeepSeek异步流式接口并保留免费mock模式，以PostgreSQL保存历史、Redis缓存短期上下文；
对3份用户资料实现条款/栏目/表格分块检索与可核验引用，使用Docker Compose提供可复现的本地部署。

## 个人贡献模板

按自己实际参与、理解和能讲清楚的部分选用；这是AI辅助的学习实践，不写成已有生产运营或完全独立研发经历。

- 实现FastAPI账号认证、个人会话及消息接口，使用Argon2密码哈希与JWT，按用户校验记录归属，统一处理越权404。
- 接入异步模型适配层，将上游流转换为SSE事件，处理超时、断开、输出截断和错误映射，持久化生成状态并保护同一会话的并发生成。
- 对3份本地资料进行结构化分块和幂等导入，保存哈希、版本和引用定位；采用小规模中文词面检索与适用范围/例外联检，服务端校验引用编号并提供鉴权原件入口。
- 使用Redis缓存已完成问答，缓存过期或不可用时从PostgreSQL恢复；区分一般分析与具体政策依据，避免资料缺口导致整体拒答。
- 完成原生响应式聊天页面及Compose本地部署，通过独立迁移服务、非root镜像和隔离数据测试验证可复现性。

## 可证明的结果

- 217项离线回归测试通过；同镜像隔离部署检查覆盖登录、原件访问、SSE、停止和重启历史保留。
- 8条虚构演示指南；3份用户文档、30片段，其中29片段可检索。
- 原预算内3次真实DeepSeek请求通过连接、流式指南回答和多轮；新增文档引用及真实停止未补做付费验收。
- 桌面1440×960与手机390×844浏览器验收、匿名截图及可复现启动命令。

不填写未经测量的QPS、吞吐、延迟优化比例、用户数量、准确率、节省成本或公开上线经历。
原有3次请求的用时仅是单次本地观测，不是性能基准。

## 面试讲解线索

1. 为什么历史以数据库为准，Redis故障后如何恢复？如何排除failed/cancelled回复？
2. SSE的网络块为何不等于事件？浏览器如何缓冲跨块事件，如何发送Bearer的POST？
3. 为什么不用Web worker启动时直接迁移？单次初始化锁如何串行，导入如何避免重复？
4. 如何在开始流前校验归属，流期间释放事务，取消后保存状态并关闭上游？
5. 引用编号校验能证明什么、不能证明什么？为什么Word不写页码，为什么流程图提取顺序不当作流程？
6. 为什么没有向量数据库？三份小文档先用可解释的词面检索，规模/同义表达增多时再评估召回方式。
