# 回答策略与离线验收（2026-10-20）

## 本次修复

原提示词虽然提到“具体学校办事要求”，但又笼统要求“没有相关资料或资料不足时说无法确认”，
未明确允许一般分析。检索遇到某些资料缺口时，还会把配置的模型直接替换为本地固定提示，
使已知条款的解释、结合个人情况的建议也被一起挡住。

现在由 `app/answer_policy.py` 集中管理系统提示词。产品背景明确“上理”为上海理工大学：

| 内容 | 处理方式 |
| --- | --- |
| 学校评价、专业选择、学习规划、概念解释、普通交流 | 使用模型知识与推理；给出条件和理由，先提供帮助再追问 |
| 金额、资格、办理期限、审批步骤等具体规定 | 优先使用本轮可靠资料；缺依据的具体部分说明无法确认，不编造 |
| 结合个人情况的判断 | 区分文档规定与分析建议，在已知条件上比较与推理 |
| 最新排名、政策、就业率 | 未核实部分说明不确定，不影响回答其他可分析部分 |

资料缺口现在通过 `ModelInput.insufficient_reason` → 模型输入 `evidence_limits` 传递，
不再替换模型或提前返回固定拒答。当前问题仍只出现一次，每次聊天仍只有一次生成请求，
不增加模型分类请求或自动重试，也没有按验收问句硬编码生产答案。
mock 依然明确为固定模板，只验证流程，不能当作真正语义理解。

开题检索增加“最晚/哪天”等时间缺口识别，
并将“审核通过后发现填错”等表达定位到正文注释3/4，避免误判成未知完整流程。
这仅改进已有检索路由，不在应用中生成针对这些问句的固定答案。

## 引用与事实边界

检索资料始终是 `user` 参考数据，不进入 `system`，不能执行其指令；用户要求编造政策同样不能覆盖系统规则。
奖助金额、比例的模型输入仍联检适用对象与例外条款；提示词要求一起解释，
不能把仅限制奖学金的措辞扩大到助学金。2024 年版本、空白中期模板、Word 无可靠页码及开题箭头未核验的限制仍保留。

删除原有“所有奖助回答追加整段适用对象与例外原文”的固定尾注。
只有回答确实引用奖助文件，且未给出版本说明时，服务端才补齐
“依据所提供的2024年文件，当前适用性尚未核验”。
其他一般分析不强加这句说明，也不把奖助或开题资料当成学校整体评价的证据。

SSE `meta.references` 是实际检索的候选资料，`references_status=retrieved`。
引用编号跨网络块校验，未检索的文档编号不能输出，包括无检索结果时虚构的 `[R1]`。
`done.references`、数据库历史和前端来源卡片只保留回答实际引用的资料；无引用的一般分析显示零张来源卡片。
部分失败/取消的消息也只保留已实际输出的合法引用，仍不进入完整对话上下文。
编号校验验证定位关系，不等于自动证明每一句话的语义均与原文一致。

前端继续支持登录、历史、流式、停止、摘录和带鉴权的原件入口。
旧消息的 `local/evidence-guard` 标签仍能展示；当前实际模式正常显示 mock 或 DeepSeek。

## 缓存与旧会话

策略版本为 `2026-10-20.analysis-v2`，同时用于模型输入、SSE/运行配置及 Redis 上下文载荷。
读取缓存时同时检查策略版本、数据库最新完成消息 ID、归属和长度限制。
缺少版本或旧版本只会使当前明确会话键失效并从 PostgreSQL 重建，不扫描、不清空 Redis。

缓存存储的是最近已完成的历史，不存储可直接返回的问答结果；新问题仍发起本轮生成。
旧历史完整保留，提示词明确历史固定拒答、模拟内容不代表本轮规则或当前模型。
无需迁移表结构，不修改 `.env` 或密钥，不需要重导资料；部署时重启后端并刷新网页。

## 网页验收

1. 重新启动现有服务或确认 `--reload` 已重载，刷新网页；无需重新填写 Key。
2. 新建会话依次发送上表问题。一般分析应先给帮助再追问，第二问应承接计算机方向与就业目标。
3. 国家助学金回答应包含2024版本提示、年标准与适用范围/相关例外，来源定位正确，不能自行推算月实发额。
4. 截止日期应明确现有资料未记载，并给出具体查询建议；修改问题应解释正文注释3/4的已知办法。
5. 在含旧拒答的会话继续问“上理怎么样”，确认按新规则分析，同时刷新后旧历史仍能查看。
6. 检查生成中停止按钮、刷新恢复和来源卡片；一般分析无需引用，真正使用文档的回答才显示对应来源。

人工检查尤其关注：模型是否把不确定性限定在具体缺失部分、是否将一般知识误说成最新校内事实、
金额解释是否遗漏相关适用对象与例外。提示词改善不等于对任意模型输出作出了事实保证。
