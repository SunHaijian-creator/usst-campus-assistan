# 回答策略

助手结合对话上下文和校园资料提供回答。“上理”指上海理工大学。

## 问题处理

| 内容 | 回答方式 |
| --- | --- |
| 学校评价、专业选择、学习规划、概念解释 | 给出有条件的分析，说明判断依据，根据需要追问 |
| 金额、资格、办理期限及审批要求 | 优先引用相关资料，保留适用范围和例外条件 |
| 结合个人情况的判断 | 区分资料规定和分析建议，根据已知条件比较方案 |
| 最新排名、政策及就业数据 | 说明未核实的信息，避免将一般知识表述为实时事实 |

资料不足时，回答应指出具体缺失信息，解释能够确定的内容，并提供进一步查询建议。

## 资料与引用

参考资料作为独立数据传入模型。文档中的指令、链接或代码不作为操作授权。

服务端将引用编号绑定到实际检索片段，保留文档名称、版本、定位和摘录。回答使用的合法引用进入消息历史及来源卡片。普通分析可以没有来源卡片。

奖助文件的适用范围、管理例外与金额标准共同参与检索。文件有效性未经确认时，回答保留版本及适用性说明。空白表格不能推出数值门槛，未经核对的流程图不能推出办理顺序。

引用编号校验用于保证来源定位合法，不能替代对回答内容的事实核查。

## 多轮对话

每次请求结合已完成的历史问答、当前问题和相关资料进行生成。失败或取消的回复不进入正常上下文。

Redis缓存校验会话归属、内容长度、最新完成消息及策略版本；缓存失效时从PostgreSQL恢复。历史消息保留在数据库中。

## 相关实现

- `app/answer_policy.py`：回答约束与策略版本。
- `app/model_gateway.py`：模型输入组织与适配器选择。
- `app/reference_search.py`：资料检索与适用范围联检。
- `app/reference_citations.py`：流式引用校验。
- `app/context_cache.py`：短期上下文缓存。
